# 进度控件架构设计（v1 · 待评审）

> 依据 `documents/进度动效设计稿.html`（04–24，共 21 个动效）设计。
> 本文只做架构与计划，不含实现代码。批准后按第 11 节分批落地。

---

## 0. 结论先行

三个决定，其余细节都由这三个决定推导出来：

1. **不是 21 个控件，是 2 个控件 + 23 套模板。**
   一个 `ProgressIndicator` 承载全部 20 个"等待/进度"视觉，靠 `Kind` 选模板；`StepTracker` 单独承载 04 步骤管线（它有集合与状态语义，不是纯视觉）。
2. **控件本体零视觉、零画刷、零时长。**
   全部视觉在 `Themes/` 里，且模板只允许引用 Token 资源键。换肤 = 换 Token 字典，模板一行不改。
3. **模板解析走"三级回退"，用户覆盖零侵入。**
   显式 `Template` > `TemplateKey` > `Progress.Template.{Kind}.{Mode}` > `Progress.Template.Default`。
   用户想改某个动效，只需在自己的资源里定义一个同名 `ControlTemplate`，不继承、不重写控件。

| 编号 | 动效 | 生成规则 |
| --- | --- | --- |

| --- | --- | --- |

## 3. `ProgressIndicator` 契约

### 依赖属性

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `Kind` | ProgressKind | `Arc` | 选视觉语言，不影响 API 用法 |
| `State` | ProgressRunState | `Idle` | 驱动 VSM，含 Success/Error 终态 |
| `IsActive` | bool | false | 运动开关，`false` 时故事板硬停 |
| `IsIndeterminate` | bool | true | 决定模板后缀与是否显示百分比 |
| `Value` / `Minimum` / `Maximum` | double | 0 / 0 / 100 | 确定态 |
| `StatusText` | string | null | 文案，如"搜索设备中" |
| `ShowStatusText` | bool | true | 只出图形时关掉 |
| `AccentBrush` | Brush? | null | null 时走 Token，非 null 时模板 `TemplateBinding` 覆盖 |
| `SpeedRatio` | double | 1.0 | 全局调速，>1 加快 |
| `Motion` | ProgressMotion | Auto | Auto 读 `SystemParameters.ClientAreaAnimation` |
| `TemplateKey` | string? | null | 显式指定模板资源键，跳过低两级回退 |

只读：`Percent`（0..1，已做区间钳制与除零保护）。确定态模板直接用 `ScaleTransform.ScaleX="{Binding Percent, RelativeSource={RelativeSource TemplatedParent}}"`，**不需要值转换器**。

### 状态契约

`ProgressRunState` 映射到模板内的 VSM 组 `ProgressStates`：

| 状态 | 模板职责 |
| --- | --- |
| `Idle` | 静止帧，不跑故事板 |
| `Running` | 进入时 `BeginStoryboard`，离开时由 VSM 自动停止 |
| `Success` / `Error` | 静止帧 + 语义色（`Progress.Brush.Success/Error`） |
| `Paused` | 保持当前视觉，不跑故事板 |

`Motion=Reduced` 时控件尝试 `GoToState("RunningReduced")`；模板未实现该状态时 `GoToState` 返回 false，控件忽略返回值，元素自然停在首帧——这是允许的降级，不要求 20 套模板都补一个静态帧。

## 4. 模板解析与自定义优先级

### 资源键规范

```
Progress.Template.{Kind}.Indeterminate     // 20 套
Progress.Template.{Kind}.Determinate       // 仅 4 个 Kind 有，其余映射到通用确定态
Progress.Template.Default                  // 兜底，任意 Kind 都能渲染
```

### 解析顺序

1. `Template` 被用户显式赋值（`ValueSource == Local` 且非内部赋值）→ 直接用，不再解析
2. `TemplateKey` 非空 → `TryFindResource`，命中即用
3. `Progress.Template.{Kind}.{Mode}` → 命中即用
4. `Progress.Template.Default`

回退过程静默，不抛异常、不写日志。命中结果通过 `SetCurrentValue` 写入，避免冲掉用户绑定；内部用标志位区分"用户设的"与"解析来的"。

### 用户自定义的四种方式（由轻到重）

| 方式 | 做法 | 影响面 |
| --- | --- | --- |
| 换色 / 换尺寸 / 换速度 | 在自己资源里重定义 `Progress.Brush.Accent` 等 Token | 全局，零模板改动 |
| 改单个动效外观 | 定义一个同名 `ControlTemplate x:Key="Progress.Template.Sonar.Indeterminate"`，合并顺序放在内置字典之后 | 该 Kind 全体 |
| 换掉整套视觉 | 设 `Template` 或写 `<Style TargetType="ProgressIndicator">` | 单实例或全局 |
| 新增设计稿里没有的动效 | 自定 `x:Key` 模板 + `TemplateKey="MyBrand"` | 单实例，不动枚举 |

第四条是关键：`Kind` 是封闭枚举保证设计器可预览，但 `TemplateKey` 是逃生舱，用户加新动效不需要等我们发版。

## 5. 复用三轴

架构的复用价值集中在三处，其余都是这三处的应用：

**轴 1 · Token 复用（纵向：主题）**
`Progress.Tokens.Light.xaml` / `Progress.Tokens.Dark.xaml` 只放值：画刷、线宽、时长、缓动、透明度、字号。模板里**禁止出现字面颜色与字面时长**（Review 时按此判定）。新增一个动效的成本 = 写一套模板，不需要想配色。

**轴 2 · 模板复用（横向：视觉）**
20 套模板共用同一组 VSM 状态名、同一个 `StatusText` 排版约定、同一套尺寸档位（`Progress.Size.{Sm|Md|Lg}`）。切换 `Kind` 不改调用方任何代码。

**轴 3 · 动画契约复用（纵向：实现手段）**
所有循环动画统一为"`IsActive=true` 时 `BeginStoryboard`，一个周期 `RepeatBehavior="Forever"`，只动 `RenderTransform` / `Opacity` / `StrokeDashOffset`"。
B 类的 5 种阵列统一为"`Phase` 0→1 循环，`OnRender` 按 Phase 出帧"。
没有第三种动画范式，评审时按此判定。

## 6. 确定进度的收敛策略

不对 20 个 Kind 做 Determinate 变体（那是 20 套额外模板，收益极低）。收敛为 **3 套模板**，按 Kind 映射：

| Kind | Determinate 模板 |
| --- | --- |
| FlowBar、CounterFlow | `Bar.Determinate`（ScaleTransform 宽度） |
| Arc、GlowRing、DualRing、其余 | `Ring.Determinate`（ArcSegment） |
| TickRing | `RingSegmented.Determinate`（刻度点亮） |

环形需要 1 个 `PercentToArcGeometryConverter`（MultiBinding：Percent + ActualWidth + ActualHeight + Thickness → Geometry）。这是本设计**唯一新增的转换器**。

## 7. `StepTracker`（04 步骤管线）

独立控件，语义与 `ProgressIndicator` 正交，共享 Token 与 `AccentBrush`。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `Steps` | `IEnumerable<ProgressStep>` | 步骤集合 |
| `CurrentIndex` | int | 当前步，-1 表示未开始 |
| `Orientation` | Orientation | Horizontal / Vertical |
| `ShowConnector` | bool | 节点连线 |
| `NodeSize` / `Spacing` | double | 尺寸档位之外的微调 |

`ProgressStep.State`：`Waiting / Active / Done / Error / Skipped`，允许显式覆盖（例如某步失败但仍继续）。
模板用 `ItemsControl` + `UniformGrid`/`StackPanel`，连线由一个 `ItemsControl` 之外的 Grid 列承载，填充比例按 `CurrentIndex` 计算，**不用转换器**——由控件的只读 `ProgressRatio` 直接绑定 `ScaleTransform.ScaleX`。

04 的 "active 节点脉冲" 用模板内的 `DataTrigger State=Active` + `BeginStoryboard`，`IsActive` 语义在 StepTracker 中由 `CurrentIndex` 是否有效决定。

## 8. 主题挂载方式（已定：引入 `Generic.xaml`，开箱即用 + 可重写）

**决策：新增 `Themes/Generic.xaml`，控件零配置即可渲染；同时保留三条重写通道。**

### 一个必须先解决的约束

`Generic.xaml` 只服务于 `DefaultStyleKey` 的主题样式解析，**其中的资源不在元素的常规资源查找链上**。
而按 `Kind` 动态取模板依赖 `TryFindResource`，如果模板放在 `Generic.xaml` 里，永远取不到，
"宿主重写某个模板键"也会一起失效。

### 解决办法：字典挂到应用资源，且插在最前

控件首次实例化时，`ProgressTheme.EnsureLoaded()` 把两个字典 `Insert(0, ...)` 进
`Application.Resources.MergedDictionaries`：

- `Progress.Templates.xaml`（模板）
- `Progress.Tokens.Light.xaml`（令牌）

`Insert(0)` 而非 `Add` 是关键：WPF 对 `MergedDictionaries` 是**倒序查找**，
插到最前意味着宿主在 `App.xaml` 中后续 merge 的同名资源永远优先命中。

`Generic.xaml` 本身只承载默认 `Style`（`Template` 用 `DynamicResource` 指向默认模板键），
不 merge 任何字典，避免出现同一字典的两份实例。

### 宿主重写进度控件的三种方式

| 方式 | 做法 | 生效范围 | 验证状态 |
| --- | --- | --- | --- |
| 换值 | 在自己资源里重定义 `Progress.Brush.Accent` 等令牌，或 merge `Progress.Tokens.Dark.xaml` | 全局 | 已验证（深色截图） |
| 换单个动效 | 定义同名 `ControlTemplate` 键，如 `Progress.Template.Sonar.Indeterminate` | 该 Kind | 已验证（示例 05） |
| 换整套样式 | `App.xaml` 里写隐式 `<Style TargetType="{x:Type p:ProgressIndicator}">`，其来源为 `ImplicitStyleReference`，优先于主题样式 | 全局 | 设计保证 |
| 接入新动效 | 自定 `x:Key` 模板 + `TemplateKey="MyBrand"` | 单实例 | 已验证（示例 07） |

### 模板接管的判定规则（易错点）

判断"模板是否由宿主提供"必须看 `BaseValueSource`：

- 主题样式给的默认值 → `DefaultStyle` / `DefaultStyleTrigger` / `Default` → **可接管**
- 宿主直接设值 → `Local`；自定义 Style → `Style` / `StyleTrigger`；隐式 Style → `ImplicitStyleReference` → **必须尊重**

> 踩坑记录：最初只判断 `!= BaseValueSource.Default`，导致主题样式（来源是 `DefaultStyle`）
> 被误认为宿主提供，全部跳过解析、静默落回兜底模板。表现为"控件能显示但完全不动"。

### 存量影响

`Generic.xaml` 里没有为任何其他控件写 `TargetType` 默认样式，
`TProgressRing`、`IconRadioButton`、`TreeComboBox` 的解析路径完全不变。

## 9. 性能与可访问性红线

**动画属性白名单**：`RenderTransform`（Translate/Rotate/Scale）、`Opacity`、`StrokeDashOffset`。禁止动画 `Width/Height/Margin/Padding`（触发布局）、禁止 `LayoutTransform`、禁止 `DropShadowEffect`/`BlurEffect`（设计稿的辉光用径向渐变模拟）。

**启停纪律**：`IsActive=false` 或 `IsVisible=false` 时不得有故事板在跑。VSM 状态切换天然满足，代码里不得出现裸 `storyboard.Begin()`。

**B 类阵列**：`PointsCount/Rows/Columns` 设上限（点阵默认 9×9=81，上限 15×15），并暴露 `MaxPrimitives`；超出时降采样而非崩溃。

**可访问性**：
- `Focusable=false`、`IsTabStop=false`（无交互）
- `AutomationProperties.Name` 自动取 `StatusText`，为空时取 `Kind.ToString()`
- `Motion=Auto` 时读 `SystemParameters.ClientAreaAnimation`，关闭系统动画则进 Reduced 态
- 不确定态**不显示百分比**，符合设计稿"不谎报进度"的原则

## 10. 文件清单

实际落地与最初的规划有出入，以本节为准。

```
YoYo.Toolkit/
├─ Controls/Progress/
│  ├─ ProgressIndicator.cs      ✅ 主控件（DP + 四级模板回退 + VSM 驱动）
│  ├─ ProgressTheme.cs          ✅ 资源挂载（MergedDictionaries.Insert(0)）+ 一次性诊断
│  ├─ StepTracker.cs            ✅ 流程步骤条
│  ├─ ProgressPainter.cs        ✅ 自绘阵列（6 个 Render* 方法，未拆策略类，见下）
│  ├─ ProgressPainterPattern.cs ✅ 阵列枚举 Signal/Ticks/TicksProgress/Wave/Matrix/Comet
│  ├─ ProgressKind.cs           ✅ 20 项枚举（带 Description 与设计稿编号）
│  ├─ ProgressRunState.cs       ✅
│  ├─ ProgressMotion.cs         ✅
│  ├─ ProgressStep.cs           ✅
│  └─ ProgressStepState.cs      ✅ Waiting/Active/Done/Error/Skipped
├─ Converters/
│  ├─ PercentToArcGeometryConverter.cs   ✅ IMultiValueConverter，0~1 → 环形弧几何
│  └─ PercentToTextConverter.cs          ✅ 0~1 → "62%"，确定态中央读数
└─ Themes/
   ├─ Generic.xaml                     ✅ 两个隐式 Style，Template 走 DynamicResource
   ├─ Progress.Tokens.Light.xaml       ✅ 只放值
   ├─ Progress.Tokens.Dark.xaml        ✅ 键名与浅色版完全一致
   └─ Progress.Templates.xaml          ✅ Default + 19 套 Indeterminate + 3 套 Determinate + StepTracker

YoYo.Toolkit.Sample/
├─ MainWindow.xaml / .xaml.cs          ✅ 演示页 + 双主题切换 + 暂停总闸
└─ App.xaml.cs                         ✅ 命令行：--shot/--height/--dark/--paused/--value/--step/--probe/--diag/--cpu
```

两处对原计划的修正：

1. **阵列没有拆成 5 个策略类**。5 种阵列共用 `ProgressPainter` 的 `DrawingContext`、`Phase`、`Count`、`Rows`、`Thickness` 等同一组输入，拆类只会把公共参数在 6 个文件里重复六遍。改成"一个 `FrameworkElement` + 6 个 `Render*` 私有方法 + 一个 `Pattern` 枚举"，新增阵列 = 加一个枚举值 + 一个方法，扩展点更窄。原本担心的"上帝类"没有出现：全文件约 260 行，无状态、无分支耦合。
2. **多了一个 `PercentToTextConverter`**。确定态如果只靠 `StatusText` 显示读数，调用方每改一次 `Value` 就要同步改一次 `StatusText`；直接在模板里绑 `Percent` 更省事。

预估 25 个新文件，实际 16 个（模板高度集中在 1 个 `.xaml`，不按 Kind 拆碎文件）。

## 11. 实施计划

分 5 批，每批结束都构建 + 冒烟，不合格不进下一批。

### 批次 1 · 骨架（✅ 已完成）

- 枚举 4 个、`ProgressIndicator`（含模板解析三级回退 + 诊断）、`ProgressTheme`、Token Light/Dark、`Generic.xaml`、`Default` 模板、`Arc.Indeterminate` 首套模板
- **验收结果**：全部通过
  - `Kind=Arc` 正常旋转，两个时间点渲染结果不同
  - `IsActive=false` 后两个时间点渲染哈希完全一致，故事板确已停止
  - merge Dark 字典后全部配色变化，模板零改动
  - `Window.Resources` 覆盖 `Progress.Template.Sonar.Indeterminate` 生效
  - 无模板的 `Kind` 静默回落 `Default`，不留空白
  - `TemplateKey` 接入自定义动效生效
- 复杂度：中

### 批次 2 · A 类 13 套模板（✅ 已完成）

- 按设计稿分组提交：条形组（07/13/22）、点组（09/14）、环形组（08/12/19/24）、扩散组（10/11/18/21/23）
- **验收结果**：20 套 Indeterminate 全部渲染出可见图形，无空白、无错位、无越界
  - `--diag` 逐 Kind 冒烟：20/20 模板应用无异常
  - 明暗两套整页截图逐卡片比对（`documents/shot-full.png`、`shot-full-dark.png`）
  - 修正 3 处视觉缺陷：`Orbit` 卫星点误用 `Canvas.Left` 落在 `Grid` 里（全部堆到圆心）→ 改为 `Canvas` 容器；`Scan` 扫描线太弱 → 加内容示意条 + 光带；`Comet` 缺轨道参照 → 补虚线环
  - 新增 `Progress.Brush.Guide` 令牌：原来是描边类引导线直接复用 `Progress.Brush.Track`（约 7% 透明度），在浅色卡片上几乎不可见
- 复杂度：中高（量大但同构）

### 批次 3 · B 类 5 种阵列（✅ 已完成）

- `Phase` 契约 + 6 个 `Render*` 方法
- **验收结果**：Release x64 / WPF Tier 2（硬件加速）/ 12 逻辑核下
  - 6 个阵列控件（140px）同时运行 4 秒：静止基线 15.40% → 运行 19.08%（单核口径）
  - 净增开销 3.68% ÷ 6 = **单控件 0.61% 单核**，达标（< 2%）
  - 整机口径 1.59%
  - 数据落在 `documents/cpu.txt`
- 复杂度：高（本轮技术含量最高的一批）

### 批次 2 阶段的排障记录（值得留档）

- **现象**：`OnApplyTemplate` 抛 `无法解析属性路径'ScaleX'中的所有属性引用`，进程直接崩，`DispatcherUnhandledException` 都拦不到。
- **两次误判**：先以为 `TargetName` 不能指向 `Freezable`，改成指向 `ScaleTransform` 无效；再以为属性路径缺类型限定符，批量改成 `(ScaleTransform.ScaleX)` 仍复现。
- **真因**：`obj/` 里的**陈旧 BAML**。模板 XAML 改对了，但增量编译没有重新生成 BAML，运行时加载的仍是旧路径。`rm -rf bin obj` 全量重建后，20 个 Kind 一次全过。
- **教训**：改 ControlTemplate 里的 `Storyboard` 后如果运行时报属性路径错误，先全量清理再怀疑语法。

### 环境踩坑

- MSBuild 并行复制偶发 `Stack overflow at Interop+Kernel32.DeleteFilePrivate`（`Copy.ParallelCopyTask`）。`-m:1`、`-p:BuildInParallel=false` 均无效；可行绕过是构建后手动 `cp -p` 同步 `YoYo.Toolkit.dll/.pdb` 到 Sample 输出目录，让 `SkipUnchangedFiles` 判定无需复制。

## 附录 B · Token 键清单（落地版）

```
Progress.Brush.Accent / AccentSoft / Secondary / Track / Guide

Progress.Thickness.Hairline(3) / Ring(4) / Track(4)

```

两处与原草案的差异：

- 删掉 `Progress.Easing.*`。WPF 的 `EasingFunction` 不是值类型资源，做成 Token 需要额外的 `Freezable` 包装，而缓动曲线本来就跟着每个模板的体感走，缓存到字典里反而不好调。缓动一律写在模板的 `KeyFrame` 上，见附录 A。
- 新增 `Progress.Brush.Guide`。`Track` 是给"填充轨道"用的（约 7% 透明度），拿它画 1px 描边引导线在浅色背景上等于没画。`Guide` 约 17%（浅色 `#2B0F1416` / 深色 `#33FFFFFF`），专供虚线环、十字线、步骤条节点描边。
